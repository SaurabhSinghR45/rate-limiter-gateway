2. Yeh Kya Problem Resolve Karta Hai?

❌ Without Rate Limiting (Khatra)

Jab gateway protection nahi hoti:

  • 💥 Server Crash: Traffic badhte hi database aur backend crash ho jaate hain.
  • 🤖 DDoS & Bot Attacks: Bots bar-bar request bhejkar server down kar dete hain.
  • 🔓 Brute-Force Exploits: Login/OTP endpoints par unlimited guesses laga sakte hain.
  • 💸 High Cloud Costs: Server par load badhne se AWS/Cloud bills achanak badh jaate hain.

✅ With Rate Limiter Gateway (Solution)

Is project ko lagane ke baad:

  • 🛡️ Zero Backend Overload: Limit ke upar aane wali extra requests backend tak pahunchti hi nahi.
  • ⚡ Fair Usage Policy: Har ek user ko barabar quota milta hai (e.g. 10 requests / 10 sec).
  • 🧱 Hidden Backend (Security): Client direct backend ko touch nahi kar sakta, gateway proxy karta hai.
  • 📈 Live Telemetry: Kaun sa IP kitni requests bhej raha hai, sab real-time track hota hai.
⚙️

3. Hum Kya Use Kar Rahe Hain Aur Kyu?

🟢

Node.js + Express 5

server.js

Core Gateway server jo saari incoming requests ko accept aur filter karta hai.

Kyu use kiya: Asynchronous Non-blocking I/O hone ki wajah se ek second mein hazaaron concurrent requests bina freeze hue handle kar leta hai.
⚡

Redis (In-Memory DB)

Port 6379

Client ke request counters aur timestamps ko real-time store karne ke liye.

Kyu use kiya: SQL/Mongo disk-based hote hain jo slow hain. Redis RAM mein chalta hai, jisse limit check hone mein <1 millisecond lagta hai.
📜

Redis Lua Scripts

src/algorithms/

Rate limit ka logic direct Redis database engine ke andar execute hota hai.

Kyu use kiya: Race conditions avoid karne ke liye! Agar ek hi millisecond mein 50 requests aayein toh calculation 100% atomic hoti hai.
🔄

http-proxy-middleware

Reverse Proxy

Jo request pass ho gayi, use target backend service par aage bhej deta hai.

Kyu use kiya: Backend code mein bina koi change kiye, gateway ke piche kisi bhi existing API (Port 3000) ko plug-and-play attach kar sakte hain.
📝

Winston Logger

Structured Logging

Har ek request aur blocked traffic ka log files mein record maintain karta hai.

Kyu use kiya: Debugging aur security auditing ke liye — exact pata rehta hai kis IP ne kab attack ya heavy traffic generate kiya.
🖥️

Web Console UI

UI/index.html

Interactive frontend test dashboard jahan buttons daba kar testing hoti hai.

Kyu use kiya: Terminal ke bina bhi koi bhi non-technical person dekh sake ki kaise 10th request ke baad server 429 block phenk raha hai.

4. 5 Rate Limiting Algorithms (Kaise Kaam Karte Hain)

Fixed Window Counter

fixedWindow

Har 10 second ka ek fixed slot hota hai. Simple counter lagta hai. Fast hai lekin window edges par 2x burst aa sakti hai.

Sliding Window Log

slidingLog

Har request ka exact timestamp Redis sorted set mein save hota hai. 100% accurate hai, lekin memory thodi zyada leta hai.

Sliding Window Counter

slidingCounter

Previous window aur current window ke counter ka weighted average nikalta hai. Fast bhi hai aur memory bhi save karta hai.

Token Bucket

tokenBucket

Bucket mein tokens refill hote hain. Har request 1 token leti hai. Short bursts allow karta hai (industry standard jaise AWS/Stripe).

Leaky Bucket

leakyBucket

Requests ek queue mein aati hain aur constant steady speed se process hoti hain. Smooth traffic flow ke liye best hai.

5. Docker Commands: Kyu Use Kar Rahe Hain Aur Isse Kya Hota Hai?

Docker Kyu Chahiye? Redis Linux ke liye natively design kiya gaya hai. Windows par Redis directly install karna mushkil aur outdated hota hai. Docker ki madad se hum 1 single command mein isolated, stable aur production-grade Redis server chala lete hain.

COMMAND 1 Download Redis Image
docker pull redis:alpine

Kyu aur Kya hota hai: Docker Hub se Redis ka sabse lightweight (~15MB) container image download karke aapke computer mein save karta hai.

COMMAND 2 Run Redis Container
docker run -d --name redis-rate-limiter -p 6379:6379 redis:alpine
Parameters ka Matlab:
  • -d (Detached): Background mein chalata hai taaki terminal block na ho.
  • --name redis-rate-limiter: Container ko yaad rakhne laayak naam deta hai.
  • -p 6379:6379 (Port Mapping): Docker container ke andar ka port 6379 aapke Windows ke `localhost:6379` se jod deta hai taaki Node.js connect kar sake.
COMMAND 3 Status Check Karo
docker ps

Kyu: Dekhne ke liye ki Redis container active hai ya band ho gaya hai.

COMMAND 4 Daily Start / Stop
docker start redis-rate-limiter
docker stop redis-rate-limiter

Kyu: Container baar-baar naya create karne ki zaroorat nahi hoti. PC restart hone par sirf docker start redis-rate-limiter chalao.
